# Vertex AI recommendation grounding runbook

This runbook covers the Milestone 11 Vertex AI path for grounded
recommendations in the development environment.

## Current safe default

Development stays safe by default:

- `AI_PROVIDER=mock`
- `VERTEX_AI_PROJECT_ID=finance-manager-dev-500423`
- `VERTEX_AI_LOCATION=us`
- `VERTEX_AI_MODEL=gemini-3.1-flash-lite`

Terraform configures the Vertex environment values and grants the worker runtime
`roles/aiplatform.user`, but Vertex calls are not made unless `AI_PROVIDER` is
changed from `mock` to `vertex`.

## Model choice

Use:

```text
gemini-3.1-flash-lite
```

Reason:

- Google Cloud documents it as the current Flash-Lite model ID.
- It is GA.
- It supports structured output and system instructions.
- It is optimized for low-latency, cost-sensitive traffic.
- It is available in the `us` multi-region.

Official source:

```text
https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-1-flash-lite
```

Before switching the deployed worker to Vertex, re-check that page because model
availability, lifecycle dates, and recommended model names can change.

## What changes when Vertex is enabled

When `AI_PROVIDER=vertex`, the worker uses Vertex AI for:

- financial analysis narrative generation;
- recommendation ranking and explanation.

Deterministic calculations and recommendation candidates still come from app
code. Vertex only receives minimized aggregate/candidate/evidence payloads and
returns JSON that is validated before storage.

## Privacy constraints

The prompt payload must not contain:

- Plaid access tokens;
- Plaid Item IDs;
- provider account IDs;
- provider transaction IDs;
- account masks;
- owner email or Firebase UID;
- raw merchant names;
- raw transaction descriptions;
- free-form user notes.

The AI package tests enforce these constraints for current prompt builders.

## Enable Vertex manually in dev

Do this only after confirming the billing budget is active.

1. Update the dev Terraform worker environment from:

   ```hcl
   AI_PROVIDER = "mock"
   ```

   to:

   ```hcl
   AI_PROVIDER = "vertex"
   ```

2. Run a Terraform plan from `infra/environments/dev`.

3. Confirm the plan only changes the worker Cloud Run environment.

4. Apply the plan.

5. Deploy current images if needed.

6. Trigger recommendation generation from the web app.

## Validation commands

Worker recommendation generation succeeded:

```bash
gcloud logging read \
  'resource.type="cloud_run_revision"
   resource.labels.service_name="finance-worker"
   jsonPayload.msg="Recommendations generated by worker"' \
  --project finance-manager-dev-500423 \
  --limit 20 \
  --format='table(timestamp,jsonPayload.userId,jsonPayload.status,jsonPayload.recommendationCount,jsonPayload.aiProvider,jsonPayload.aiModel,jsonPayload.promptVersion)'
```

Worker recommendation generation failed:

```bash
gcloud logging read \
  'resource.type="cloud_run_revision"
   resource.labels.service_name="finance-worker"
   jsonPayload.msg="worker recommendation generation task failed"' \
  --project finance-manager-dev-500423 \
  --limit 20 \
  --format='table(timestamp,jsonPayload.err.message)'
```

IAM check:

```bash
gcloud projects get-iam-policy finance-manager-dev-500423 \
  --flatten='bindings[].members' \
  --filter='bindings.members:worker-runtime@finance-manager-dev-500423.iam.gserviceaccount.com AND bindings.role=roles/aiplatform.user' \
  --format='table(bindings.role,bindings.members)'
```

## Rollback

Set:

```hcl
AI_PROVIDER = "mock"
```

Then plan and apply Terraform. The worker returns to the mock provider and stops
making Vertex calls.

The `VERTEX_AI_*` environment values and IAM role can remain in place while the
provider is disabled. They do not create generation cost by themselves.

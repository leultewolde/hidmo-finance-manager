# Recommendation operations runbook

This runbook covers Milestone 11 recommendation generation in the deployed
development environment.

## Current safe default

Development should normally run with:

- `AI_PROVIDER=mock`
- `VERTEX_AI_PROJECT_ID=finance-manager-dev-500423`
- `VERTEX_AI_LOCATION=us`
- `VERTEX_AI_MODEL=gemini-3.1-flash-lite`

The deterministic policy engine creates recommendation candidates before any AI
provider is called. The AI provider can rank and explain supplied candidates,
but it cannot create new financial facts.

## Dashboard validation

Use this after deploying recommendation changes:

1. Open the deployed web app.
2. Sign in with the owner account.
3. Confirm the dashboard shows a **Recommendations** section under financial
   analysis.
4. Click **Refresh recommendations**.
5. Wait for the queued task to complete, then refresh the dashboard.
6. Confirm each recommendation shows:
   - title and rationale;
   - priority and status;
   - evidence details;
   - assumptions or limitations;
   - confidence;
   - formula, policy, provider, model, and prompt metadata;
   - planning-assistance disclaimer.
7. Expand the evidence section and confirm the recommendation only refers to
   visible deterministic evidence.
8. Test **Accept** and **Dismiss** on one recommendation.
9. Refresh the dashboard and confirm the selected status persists.

## Log validation commands

Successful worker generation:

```bash
gcloud logging read \
  'resource.type="cloud_run_revision"
   resource.labels.service_name="finance-worker"
   jsonPayload.msg="Recommendations generated by worker"' \
  --project finance-manager-dev-500423 \
  --limit 20 \
  --format='table(timestamp,jsonPayload.userId,jsonPayload.status,jsonPayload.recommendationCount,jsonPayload.aiProvider,jsonPayload.aiModel,jsonPayload.promptVersion,jsonPayload.aiLatencyMs,jsonPayload.aiPromptTokens,jsonPayload.aiCompletionTokens,jsonPayload.aiEstimatedCostMicros)'
```

Worker task failures:

```bash
gcloud logging read \
  'resource.type="cloud_run_revision"
   resource.labels.service_name="finance-worker"
   jsonPayload.msg="worker recommendation generation task failed"' \
  --project finance-manager-dev-500423 \
  --limit 20 \
  --format='table(timestamp,jsonPayload.err.code,jsonPayload.err.message)'
```

Web enqueue failures:

```bash
gcloud logging read \
  'resource.type="cloud_run_revision"
   resource.labels.service_name="finance-web"
   jsonPayload.msg="Recommendation generation enqueue failed"' \
  --project finance-manager-dev-500423 \
  --limit 20 \
  --format='table(timestamp,jsonPayload.errorName)'
```

List Terraform-managed recommendation alert policies:

```bash
gcloud monitoring policies list \
  --project finance-manager-dev-500423 \
  --filter='displayName:"recommendation"' \
  --format='table(displayName,enabled,name)'
```

## Monitoring expectations

Terraform manages log-based policies for:

- web recommendation enqueue failures;
- worker recommendation generation task failures;
- worker recommendation grounding/provider/schema failures.

Success logs include provider/model/prompt metadata plus latency, byte counts,
token counts when the provider supplies them, and estimated cost when a provider
implementation supplies it. The current mock provider has no token or cost
metadata. Vertex token counts are populated from Vertex usage metadata when
available.

Do not log prompt bodies, raw transaction descriptions, Plaid identifiers,
account masks, owner identity, or free-form notes.

## Vertex validation

Use [the Vertex recommendation grounding runbook](./vertex-recommendations-runbook.md)
before switching development from `AI_PROVIDER=mock` to `AI_PROVIDER=vertex`.

Before enabling Vertex:

1. Confirm the billing budget is active.
2. Confirm the worker runtime has `roles/aiplatform.user`.
3. Re-check the selected model in official Google Cloud documentation or the
   Vertex AI console.
4. Plan Terraform locally and confirm only the worker environment changes.
5. Switch back to `mock` after validation unless Vertex testing is still active.

## Failure triage

For dashboard refresh errors:

1. Check `finance-web` logs for enqueue failures.
2. Check the `ai-analysis` Cloud Tasks queue.
3. Check `finance-worker` logs for task failures.
4. If the failure has `AI_OUTPUT_INVALID`, inspect whether the provider output
   violated evidence, schema, or prohibited-claim rules.
5. If the failure has `AI_PROVIDER_REQUEST_FAILED` or
   `AI_PROVIDER_AUTH_FAILED`, verify Vertex IAM, region, model, and billing.

For empty recommendations:

1. Confirm a financial analysis snapshot exists for the current period.
2. Confirm the deterministic policy engine has enough data to create
   candidates.
3. Check for data-quality recommendations indicating stale or unreviewed input.
4. Trigger a manual refresh from the dashboard.

## Milestone 11 final deployed checklist

Milestone 11 is complete when the following are verified in development:

- Deterministic recommendation candidates are generated before AI grounding.
- Every stored recommendation references valid deterministic evidence IDs.
- Unknown evidence references and unsupported claims are rejected.
- Recommendation prompts exclude Plaid credentials, Plaid IDs, provider IDs,
  account masks, owner identity, raw descriptions, and free-form notes.
- Repeated dashboard loads do not call Vertex AI.
- Manual dashboard refresh queues asynchronous recommendation work through
  Cloud Tasks.
- Repeated manual refreshes are cooldown-protected by idempotency keys.
- The dashboard shows recommendations, evidence, assumptions, metadata,
  planning disclaimer, and accept/dismiss controls.
- Recommendation status changes persist across refreshes.
- Worker success logs expose provider/model/prompt, latency, token/byte, and
  cost metadata without prompt bodies.
- Log-based alert policies exist for web enqueue, worker task, and grounding
  failures.
- The Vertex path is documented and remains disabled by default in development.
- The normal deploy flow can deploy recommendation changes without Terraform
  unless infrastructure settings changed.

# Financial analysis runbook

This runbook covers the Milestone 10 AI-assisted financial analysis path in the
development environment.

## What the feature does

The dashboard can queue a financial analysis for the current month. The web
service creates a Cloud Task in the `ai-analysis` queue. Cloud Tasks invokes the
private worker endpoint, and the worker:

1. builds an aggregate analysis input from persisted accounts, debts,
   transactions, splits, and balances;
2. calculates deterministic finance metrics in `@hidmo/finance-engine`;
3. stores an analysis snapshot and job;
4. calls the configured AI provider for narrative text;
5. stores the completed narrative on the snapshot.

Core numbers must come from deterministic code. The AI provider only writes
plain-language explanation and recommendations from the structured summary.

## Current development configuration

Development uses:

- queue: `ai-analysis`;
- worker endpoint: `/tasks/financial-analysis`;
- provider: `AI_PROVIDER=mock`;
- model: `mock-financial-analysis-v1`;
- formula version: `financial-analysis-summary/v1`;
- prompt version: `financial-analysis-narrative/v1`.

Because the provider is `mock`, normal development analysis runs should not
generate Vertex AI cost.

## Privacy and prompt rules

The analysis payload sent to the AI provider is aggregate-first:

- no Plaid access tokens;
- no Plaid Item IDs;
- no provider account IDs;
- no provider transaction IDs;
- no account numbers, routing numbers, or masks;
- no raw merchant names or raw transaction descriptions;
- no user email address.

The prompt builder rejects blocked field names before provider invocation. The
stored snapshot keeps deterministic summary JSON and narrative JSON separate so
we can audit what numbers were used and what text was generated.

Before enabling `AI_PROVIDER=vertex`, verify:

1. the prompt/privacy tests pass;
2. the configured Vertex model is approved for this use;
3. the dashboard disclaimer remains visible;
4. the budget alert is still in place;
5. no raw transaction detail is added to the prompt.

## Log checks

Worker analysis completed:

```bash
gcloud logging read \
  'resource.type="cloud_run_revision"
   resource.labels.service_name="finance-worker"
   jsonPayload.msg="Financial analysis generated by worker"' \
  --project finance-manager-dev-500423 \
  --limit 20 \
  --format='table(timestamp,jsonPayload.userId,jsonPayload.status,jsonPayload.snapshotId,jsonPayload.jobId,jsonPayload.formulaVersion,jsonPayload.aiProvider,jsonPayload.aiModel)'
```

## Troubleshooting

Start with the dashboard:

- `Queued`: Cloud Tasks has accepted the work. Refresh after a few seconds.
- `Running`: the worker started the job. Wait briefly and refresh.
- `Succeeded`: the snapshot should be visible in the card.
- `Failed`: inspect worker logs and the error code on the job/snapshot.

Common causes:

- missing or wrong Cloud Tasks queue environment variables;
- `tasks-invoker` service account cannot invoke the worker;
- worker does not allow the `ai-analysis` queue;
- database connectivity failure;
- malformed task payload;
- AI provider failure;
- Vertex project/location/model missing after switching from `mock` to
  `vertex`.

Do not intentionally break service account permissions or secrets to test
alerts. Add a safe synthetic test signal first if alert firing needs to be
validated end to end.
